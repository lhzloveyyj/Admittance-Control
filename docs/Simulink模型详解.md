# Simulink 模型详解

## 1. 模型总览

运行 `build_admittance_sim.m` 后生成 `admittance_control.slx`，在 MATLAB 中双击打开。

**信号从左到右流动，最右边的输出绕回最左边形成闭环。**

## 2. 逐模块详解

### 2.1 Step_Fuser / Sine_Fuser — 测试信号

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Step` / `Sine Wave` |
| 作用 | 产生模拟的人手推力 |
| 阶跃参数 | 0.5s 时刻从 0 跳变到 10N |
| 正弦参数 | 振幅 ±5N，频率 0.5Hz |

**物理含义：** 仿真中没有人真的在推设备，用这两个信号代替。"阶跃"模拟人突然推住不动，"正弦"模拟人来回推拉。

---

### 2.2 Switch — 切换开关

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Manual Switch` |
| 作用 | 双击切换，选择阶跃或正弦信号 |

`sw='1'` = 阶跃测试，`sw='0'` = 正弦测试。

---

### 2.3 ForceSum — 力传感器物理方程

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Sum`（求和） |
| 输入符号 | `\|+-`（端口1=+, 端口2=-） |
| 运算 | `F_sensor = F_human - F_assist` |

**这是整个模型中最核心的物理方程。** 力传感器安装在手柄和机身之间，读到的力 = 人推力 减去 电机助力。

- 人推 10N，电机还没响应 → 传感器 = +10N
- 电机产生 10N 助力 → 传感器 = 0N（目标状态）
- 电机助力超过人手推力 → 传感器变负（设备在"推"人）

**在模型中：** 端口1 接 Switch（F_human），端口2 接 Force_Conv 的输出（F_assist）。

---

### 2.4 DeadZone — 死区

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Dead Zone` |
| 脚本参数 | `dead_zone = 0.15` N |
| 区间 | -0.15N ~ +0.15N |

**物理含义：** 传感器在零附近有微小噪声。如果没有死区，即使没人碰设备，控制器也会读到 0.01N、0.02N 的波动，积分项会持续累积，导致电机缓慢漂移。

**死区的作用：** 力小于 0.15N 时强制输出 0，电机不响应。手轻触（<15克力）不触发，真正推拉时才响应。

**在模型中：** 输入在 [-0.15, +0.15] 范围内 → 输出 0；超出范围 → 原样输出。

---

### 2.5 LowPass — 低通滤波器

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Transfer Fcn`（一阶传函） |
| 脚本参数 | `filt_fc = 20` Hz |
| 传函 | `1 / (τ_f·s + 1)`，其中 `τ_f = 1/(2π·20) ≈ 0.008` s |

**物理含义：** 真实的力传感器输出含有高频噪声（震动、电路噪声等）。20Hz 低通滤波器滤掉高频分量，保留人手推拉的频率成分（人手动作通常在 5Hz 以下）。

**Bode 图直观理解：**
- 0~20 Hz：信号几乎无衰减通过
- 20 Hz 以上：每倍频程衰减 6dB
- 100 Hz 噪声：衰减到原来的 ~20%

---

### 2.6 Noise — 测量噪声

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Random Number` |
| 脚本参数 | `noise_std = 0.05` N |
| 分布 | 高斯分布 N(0, 0.05²) |

**物理含义：** 模拟真实传感器不可避免的随机测量噪声。标准差 0.05N ≈ 5克力，对于低成本力传感器是合理的。

**在模型中：** 噪声加到低通滤波后的信号上（AddNoise 模块），模拟 ADC 量化噪声 + 电路噪声。

---

### 2.7 Force_PI — 力外环 PI 控制器

| 属性 | 值 |
|---|---|
| Simulink 模块 | `PID Controller`（模式 = PI） |
| 脚本参数 | `Kp_f = 3.0`, `Ki_f = 6.0` |
| 传函 | `3 + 6/s` |

**物理含义：** 这是导纳控制的最外层。输入是力传感器读数 `F_sensor`，输出是"虚拟力"`F_virtual`。

| 项 | 作用 | 没有它会怎样 |
|---|---|---|
| P（Kp=3） | 力越大 → 输出越大 → 电机加速越快 | 响应变慢 |
| I（Ki=6） | 累积力误差，持续调整直到传感器归零 | **传感器永远不归零！** 这是关键，见 2.7.1 |

#### 2.7.1 为什么必须有 I（积分）项

没有积分时，稳态传感器力不为零：

$$F_{sensor}(\infty) = F_{human} \cdot \frac{B_d}{B_d + K_{sys}} \neq 0$$

**直观理解：** 匀速推动设备需要恒定的电机速度。纯比例控制下 `v_des = Kp × F_sensor/ (导纳)`，要维持非零速度，F_sensor 必须非零 → 用户一直感到阻力。

积分项的作用：如果 F_sensor > 0，积分值持续累加，速度指令持续增大，直到 F_sensor 被推到 0。此时积分值稳定在"刚好维持当前速度"的值上。

**在模型中：** 双击 `Force_PI` 模块 → 修改 P 和 I 参数。

---

### 2.8 Admittance — 导纳滤波器

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Transfer Fcn`（一阶传函） |
| 脚本参数 | `M_d = 0.5` kg, `B_d = 1.0` N·s/m |
| 传函 | `1 / (0.5·s + 1.0)` |

**物理含义：** 这是"导纳"的核心 —— 将力映射为运动。它像一个低通滤波器，把 Force_PI 输出的"虚拟力"转换为"期望速度"。

**频域视角：**

$$V_{des}(s) = \frac{F_{virtual}(s)}{M_d s + B_d}$$

| 频率范围 | 行为 |
|---|---|
| $\omega \ll B_d/M_d$（低频） | $V_{des} \approx F_{virtual}/B_d$（力→速度的稳态增益） |
| $\omega \gg B_d/M_d$（高频） | $V_{des} \approx F_{virtual}/(M_d s)$（积分，平滑突变力） |

**M_d 和 B_d 的调节口诀：**

| 参数 | 增大 | 减小 |
|---|---|---|
| B_d | 阻力感大，速度稳 | 省力，但可能太飘 |
| M_d | 启动慢，速度变化平滑 | 跟手，但可能不平顺 |

**在模型中：** 双击 `Admittance` 模块 → 修改 Denominator `[M_d, B_d]`。

---

### 2.9 VelLimit — 速度限幅

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Saturation` |
| 脚本参数 | `V_max = 300` rad/s |
| 限制范围 | [-300, +300] rad/s |

**物理含义：** 防止导纳控制器输出超过电机物理极限的速度指令。例如电机最高转速 3000 rpm ≈ 314 rad/s，限幅设 300 rad/s。

---

### 2.10 VelErr — 速度误差

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Sum` |
| 输入 | 端口1: `v_des`（期望速度）, 端口2: `ω_actual`（实际速度） |
| 运算 | `error = v_des - ω_actual` |

**物理含义：** 这是 FOC 速度环的误差计算。对应你固件中的 `speed_error = speed_setpoint - speed_feedback`。

---

### 2.11 Vel_PI — FOC 速度环 PI 控制器

| 属性 | 值 |
|---|---|
| Simulink 模块 | `PID Controller`（模式 = PI） |
| 脚本参数 | `Kp_v = 0.05`, `Ki_v = 2.0` |
| 输出 | `Iq_ref`（交轴电流指令） |
| 输出限幅 | ±5A |

**物理含义：** 这就是你 FOC 固件中的**速度环 PI 控制器**。输入速度误差，输出 Iq 电流指令。

**对应你固件中的代码逻辑：**

```c
float speed_error = speed_setpoint - speed_feedback;
integral_speed += speed_error * DT;
float Iq_ref = Kp_v * speed_error + Ki_v * integral_speed;
Iq_ref = CLAMP(Iq_ref, -Iq_max, +Iq_max);
```

**在模型中：** 双击 `Vel_PI` 模块，可以直接填入你 FOC 固件中实际使用的 Kp_v 和 Ki_v。

**参数说明：**
- `Kp_v`：速度误差 1 rad/s → 输出多少 A 电流
- `Ki_v`：累积 1 rad 的位置误差 → 输出多少 A 电流
- `Iq_max`：最大允许电流，保护电机和驱动器

---

### 2.12 Current_Loop — FOC 电流环

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Transfer Fcn` |
| 脚本参数 | `tau_i = 0.001` s |
| 传函 | `1 / (0.001·s + 1)` |
| 带宽 | ~160 Hz |

**物理含义：** 这是 FOC 电流环的等效模型。电流环运行在 16kHz，响应极快，简化为一个一阶惯性环节。

**为什么简化：** 电流环带宽（~1kHz）远高于速度环（~50Hz）和力环（~2Hz），对外环来说，电流环几乎就是一个"瞬间响应"的增益。

**在模型中：** 输入 = `Iq_ref`（速度环输出），输出 = `Iq`（实际电机电流）。

---

### 2.13 Torque_Gain — 转矩常数

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Gain` |
| 脚本参数 | `K_t = 0.04` N·m/A |
| 运算 | `Torque = K_t × Iq` |

**物理含义：** 无刷电机的核心特性 —— 电流和转矩之间的线性关系。1A 电流产生 0.04 N·m 转矩。

**对应你的 FOC 知识：** `K_t = (3/2) × 极对数 × 永磁磁链`。FOC 中 Iq 直接控制转矩，Id 控制磁场（通常保持为 0）。

---

### 2.14 Motor_Mech — 电机机械动力学

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Transfer Fcn` |
| 脚本参数 | `J = 5e-6` kg·m², `B_m = 2e-4` N·m·s/rad |
| 传函 | `1 / (5e-6·s + 2e-4)` |
| 物理方程 | $J \frac{d\omega}{dt} + B_m \omega = T_{motor}$ |

**物理含义：** 这是电机转子的运动方程 —— 电磁转矩克服惯性（J）和摩擦（B_m）来产生转速。

**时域理解：**
- 给电机加转矩 → 角加速度 = 转矩 / J（惯性越大加速越慢）
- 达到稳态时 → 角速度 = 转矩 / B_m（摩擦越大稳态速度越小）

**输出：** `ω_actual`（实际角速度 rad/s），同时反馈给 VelErr 做速度闭环。

**时间常数：** $\tau_m = J / B_m = 5\times10^{-6} / 2\times10^{-4} = 0.025$ s（25ms），即电机从 0 加速到稳态的 63% 需要 25ms。

---

### 2.15 Force_Conv — 力换算

| 属性 | 值 |
|---|---|
| Simulink 模块 | `Gain` |
| 脚本参数 | `N_gear × η / r_wheel = 50 × 0.85 / 0.025 = 1700` |
| 运算 | `F_assist = Torque × 1700` |
| 结合 Torque_Gain | `F_assist = Iq × K_t × N_gear × η / r_wheel = Iq × 68` N/A |

**物理含义：** 电机转矩经过减速器放大、克服传动损耗、通过轮子转化为地面推力。

$$F_{assist} = \frac{T_{motor} \cdot N_{gear} \cdot \eta}{r_{wheel}}$$

| 环节 | 作用 | 数值 |
|---|---|---|
| 电机转矩 | $T = K_t \times I_q$ | 0.04 N·m/A |
| 减速器放大 | $\times N_{gear}$ | ×50 |
| 传动损耗 | $\times \eta$ | ×0.85 |
| 轮子转化 | $\div r_{wheel}$ | ÷0.025 m |
| **合计** | **68 N/A** | **1A → 68N 助力** |

**验证：** 仿真中 Iq=0.145A → F_assist = 0.145 × 68 = 9.86N ≈ 10N（人手推力），确认正确。

**输出：** `F_assist` 连接到 ForceSum 的负反馈端口，形成闭环。

## 3. 三个反馈回路

模型中包含三层嵌套反馈：

### 回路 1：力反馈（最外层）

```
ForceSum → DeadZone → LowPass → ... → Force_Conv → F_assist ──→ ForceSum(-)
```

**作用：** 电机产生的助力抵消人手推力，使力传感器归零。**带宽 ~2Hz。**

### 回路 2：速度反馈（中间层）

```
VelErr → Vel_PI → Current_Loop → Torque → Motor_Mech → ω_actual ──→ VelErr(-)
```

**作用：** 实际转速跟踪期望转速。**带宽 ~50Hz**（由 Kp_v, Ki_v 决定）。

### 回路 3：电流反馈（最内层）

包含在 `Current_Loop` 的简化模型内。实际 FOC 中，电流环是 PI 控制器 + SVPWM，带宽 ~1kHz，在此模型中简化为一阶惯性环节。

## 4. 与你 FOC 固件的对应关系

| Simulink 模块 | FOC 固件中的对应代码 | 参数 |
|---|---|---|
| `Force_PI` | `admittance_control_step()` 中的力环 PI | Kp_f, Ki_f |
| `Admittance` | `admittance_control_step()` 中的导纳滤波器 | M_d, B_d |
| `VelErr` | `speed_error = speed_setpoint - speed_feedback` | — |
| `Vel_PI` | 速度环 PI 控制器 | Kp_v, Ki_v, Iq_max |
| `Current_Loop` | 电流环 PI + SVPWM（简化） | tau_i |
| `Torque_Gain` | `K_t = 3/2 × pole_pairs × flux_linkage` | K_t |
| `Motor_Mech` | 电机转子运动方程 | J, B_m |
| `Force_Conv` | 减速比 × 效率 / 轮半径 | N_gear, η, r_wheel |

**实操建议：** 将你 FOC 固件中实际的速度环 Kp_v、Ki_v、电流环带宽、电机 K_t、J 等参数填入脚本，然后运行仿真，就能看到导纳控制器 + 你的真实 FOC 参数的整体表现。

## 5. Scope 各通道含义

| 通道 | 信号 | 含义 |
|---|---|---|
| Ch1 | `F_user`（蓝） | 人手推力输入 |
| Ch2 | `F_sensor`（黑） | 力传感器读数，目标是 0 |
| Ch3 | `F_assist`（红） | 电机实际产生的助力 |
| Ch4 | `v_des`（蓝） | 导纳控制器输出的期望速度 |
| Ch5 | `ω_actual`（红） | 电机实际转速 |
| Ch6 | `Iq`（绿） | FOC 交轴电流 |

---

## 6. 修改参数的方法

### 方法 1：修改脚本参数后重新运行（推荐）

编辑 `build_admittance_sim.m` 中对参数行，然后 `run('build_admittance_sim.m')`。

### 方法 2：在 Simulink 中直接双击模块修改

打开 `admittance_control.slx`，双击任意模块修改参数，然后点顶部绿色 `Run` 按钮重新仿真。

| 要调的参数 | 双击哪个模块 |
|---|---|
| 力环 P/I | `Force_PI` |
| 手感 M/B | `Admittance`（修改 Denominator） |
| 速度环 P/I | `Vel_PI` |
| 电流环带宽 | `Current_Loop` |
| 电机 J/B | `Motor_Mech` |
| 死区 | `DeadZone` |

---

## 7. 典型调试流程

1. **打开模型：** `open_system('admittance_control')`
2. **切换测试信号：** 双击 `Switch`，选 Step（阶跃）或 Sine（正弦）
3. **运行仿真：** 点绿色 ▶ Run 按钮
4. **查看 Scope：** 双击 `Scope` 观察 6 通道波形
5. **调节参数：** 双击对应模块修改参数
6. **重新仿真：** 再点 Run
7. **对比效果：** Scope 中会保留上一次的曲线（灰色），方便对比
